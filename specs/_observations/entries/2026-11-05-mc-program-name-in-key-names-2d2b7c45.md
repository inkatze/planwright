- 2026-11-05 [planwright] Mission control program keys embed the program name: program_<name>_<field> (repositories, spec_root, home, duties, budget, sources). When the adopter layer is rendered from a public template whose values come from a secret store (for example a dotfiles repository that keeps employer details encrypted), the program name still appears in the template as part of every key name, so a program named after an employer or client leaks through a public repository even though every value is secret. Proposal to consider: a form where program names live only in values, for example numbered or slot keys (mission_control_program_1: <name>, program_1_repositories: [...]) or a single program map per slot, so a template can carry neutral key names and take every identifying string from the secret store. Raised from a first run on a second machine.
