- 2026-11-06 [planwright] policy-guard follows a literal `cd X` whenever its own terminator is && ; or a newline, without asking whether the cd runs: after `false &&`, `true ||`, or inside an if/while/until body it may not, yet later acts are judged as running in X. Review probes (on main and on this branch) deferred `cd <primary on main>; false && cd <unit>; git push` and the same with `git commit --amend`, so a push or amend lands on main; on the primary-launch shell path, `cd <sibling>; false && cd <own worktree>; git merge origin/main` merges into the sibling. Fix shape: follow a cd only when it runs unconditionally (first segment or after ; with no || earlier in its and-or list and no open compound body), otherwise mark the directory unreadable so need_dir refuses.
