- 2026-09-07 [planwright] A written naming rule was followed exactly on every surface it enumerates and broken continuously on the one it does not, and the gap is SCOPE rather than content. The rule ("Write outward-facing text for a human without the spec open... a human would never write 'REQ-F.2b' unprompted") lists PR titles and bodies, review comments and replies, and commit messages. It says nothing about live conversation with the operator. MEASURED on this session: every PR title and every commit subject the tower produced was clean plain language with zero bare identifiers, while the tower referred to a test case by its ordinal ("c12") in conversation across roughly eleven turns, and the operator asked what it meant THREE times before the label was dropped. Twice the tower answered by re-explaining the mechanism and keeping the label, which does not help: when the operator asks what a name means, the name is the defect, not the explanation around it. The label denotes nothing but position -- tests/test-fleet-streamjson.sh numbers its cases c1..cN and this was the twelfth -- so it carries no meaning at all to a reader without that file open, which is the worst kind of token to speak. WHY THIS SURFACE IS THE HARD ONE: conversation is the only outward-facing surface with no artifact on disk, so no `check` task can ever see it; a guard that lints PR bodies for identifiers would have passed this session unchanged. The fix is therefore doctrine, not enforcement, and it is weaker for it -- recorded plainly because this repo's standing preference is a guard over a rule, and here no guard exists. doctrine/interaction-style.md now names speech explicitly, with the test stated from the listener's side (if answering "what is that?" needs the operator to open something, it is not a word to say to them). Worth generalising when writing any future doctrine rule: enumerating the surfaces a rule covers silently exempts every surface omitted, and the omitted one here was the only one a human was reading in real time.
