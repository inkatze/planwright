- 2026-09-02 [planwright] The audit for over-conservative AI-era postures found the opposite: a practice in active use that doctrine says cannot exist. doctrine/autonomous-safe-decision.md states a worker harness tool-permission prompt is one "which a tower never answers at any tier", and fleet-attention.sh enforces the tower-side path mechanically (refusing a permission-park record, "the harness permission gate stays the human/s"). fleet-streamjson.sh answer is exempt only because its header requires "an operator-recorded answer as input", and no skill invokes it. But in the 2026-09-02 fleet session the tower invoked it roughly forty times, deciding each allow itself against a STANDING operator policy recorded 2026-08-18 (relay allow for repo/plugin script invocations, purely read-only shapes, and — added that day — writes into self-created temp dirs). Doctrine has no concept of a standing policy: it models the answer as a per-request operator act, so a delegated policy is neither authorized nor forbidden, just unmodelled, and the sanctioned-channel argument silently stops covering the case. The gap is not academic: several answers that session fell OUTSIDE the standing policy and were the tower own judgment — a test spawning a tmux session, a `git push -u` of a task branch, and a twelve-way concurrent test run. Each was surfaced to the operator in the turn, so nothing was hidden, but surfacing is not the same as the operator deciding, which is exactly the line the invariant draws. Candidates: model standing permission policy as a first-class, written, auditable artifact with a declared shape-allowlist and an explicit rule that anything outside it queues; or state plainly that no delegation is possible and have the tower stop answering entirely, which would make unattended fleet operation depend wholly on the worker-settings allowlist and the PreToolUse auto-approve hook. Secondary, minor: skills/orchestrate/SKILL.md states the never-answer rule more broadly than the doctrine that owns it, so a reader who has not opened doctrine/inter-orchestrator-coordination.md reads it as forbidding the sanctioned operator channel too.
