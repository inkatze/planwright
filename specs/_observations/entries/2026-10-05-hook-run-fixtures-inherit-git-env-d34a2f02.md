- 2026-10-05 [planwright] Test fixtures that run git inside a git hook inherit GIT_DIR and GIT_INDEX_FILE from the hook, so a fixture's git -C <scratch> init/commit/checkout acts on the real repository instead of its scratch directory. On 2026-10-05 one such run inside a pre-commit hook committed onto a task branch, created and switched to a stray branch, and set core.bare=true in the shared clone config, after which every planwright script refused with "this repository has no primary working tree" until the operator reset it (resolve-root.sh now names core.bare and the repair in that case). Some test files already unset the git environment at their top (tests/test-resolve-root.sh does), but nothing requires it of a suite that hooks run. Candidate planwright work: the worker command guard or the hook doctrine flags hook-run suites that call git without clearing the git environment (env -u GIT_DIR -u GIT_INDEX_FILE ...). That touches the guard, so it is spec work, not a flight. The repeated unexplained rewrites of the shared core.hooksPath (obs:db015ded and its predecessors) may share this mechanism; unverified.
