- 2026-11-06 [planwright] policy-guard reads the directory only from literal `cd X` segments, so it misplaces later acts two ways (review probes, 2026-11-06, each deferred a git push that bash ran in a main checkout). A directory change made another way is unseen, leaving acts judged in the old directory: `eval cd <main>`, `. ./x.sh` whose script cds, `trap 'cd <main>' DEBUG` or ERR, `command -p cd <main>` (the wrapped-command branch never sees the cd), and `for x do cd <main>; done` with no `in` list (the cd shares the `for` segment, so it is never the segment's verb), and `builtin -- cd <main>` (segment_words skips builtin but not the `--`, so the verb reads as `--`); in zsh, reasoned not probed, `repeat 1 cd <main>`, `chdir <main>` (zsh's cd synonym, which the cd case does not name) and the short form `if [[ ... ]] cd <main>` (the cd shares the `if` segment). And a literal cd that no longer changes directory is still followed, leaving acts judged in its target: `enable -n cd`, or `shopt -s expand_aliases` then `alias cd=true`, earlier in the command. Fix shape: after any eval, source, trap, enable, alias or shopt segment, or a wrapped command naming cd/pushd/popd, mark the directory unknown so need_dir refuses.
