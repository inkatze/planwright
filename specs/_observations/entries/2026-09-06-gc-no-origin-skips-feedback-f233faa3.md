So the genuine single-host solo posture, the one the fence itself treats as a first-class case (fence exits 5 there and dispatch proceeds unfenced), loses the completion half of the loop entirely rather than degrading. The disabled half is unaffected, since crash-record needs no remote. Proposed: hoist the terminal report above the origin precondition in gc, so a no-origin checkout still reports completion and only the ref retirement degrades. Not applied here because it reorders a precondition in a command whose exit codes other callers branch on.
