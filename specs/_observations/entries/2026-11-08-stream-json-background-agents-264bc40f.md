- 2026-11-08 [planwright] scripts/background-job-guard.sh refuses only Bash run_in_background calls, and only the worker profile wires it. An Agent call runs in the background by default and ends in the same completion notice a stream-json session never resumes on, so a stream-json worker that fans out background subagents and ends its turn can stall the same way. Mission-control and tower sessions that mission-control-launch.sh starts on the stream-json rung carry the PLANWRIGHT_SESSION_BACKEND mark but their profiles (config/mission-control-settings.json, config/tower-settings.json) wire no guard. Extending the guard to the Agent matcher and to those profiles changes permission profiles, so it was left out of the flight that added the guard.
