- 2026-11-15 [planwright] (hub, under r-14) A suite routed to the offload Mac through scripts/fleet-remote.sh compute can fail there with a mise trust error while passing locally: tests/test-tmux-identity.sh failed this way on every routed run on 2026-11-15. The run worktree sits inside the fleet account's home (/Users/<account>/dev/.planwright-compute/run.*/wt), and the suite's E() runs commands under env -i with a temp HOME, so mise walks up from the cwd, finds /Users/<account>/.config/mise/config.toml as a project config, and looks for its trust record in the temp HOME, where there is none ("Config files in /Users/<account>/.config/mise/config.toml are not trusted"; before the host trusted the compute root, the same error named the run worktree's own mise.toml). The operator's manual workaround, trusting the compute root in the fleet account's global mise config, cleared only that first form: no host trust setting or mise trust reaches a swapped HOME, and an environment-only fix in fleet-remote.sh (exporting MISE_TRUSTED_CONFIG_PATHS or MISE_CEILING_PATHS for the run) cannot work because env -i strips it. Recommended fix: (a) the suite pins its own ceiling, E() passing MISE_CEILING_PATHS through its env -i so mise stops before the account's ~/.config/mise; the suite never cds into $tmp, so the ceiling has to be an ancestor of the cwd (the run root), not $tmp; plus (b) as the routing default, a compute run root outside the account's HOME so the upward walk never reaches ~/.config/mise. (a) is unverified: scripts/compute-route.sh runs a worktree with uncommitted changes locally, so a scratch edit of E() never reached the Mac.
