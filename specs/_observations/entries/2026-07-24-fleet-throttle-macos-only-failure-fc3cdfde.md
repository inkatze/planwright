- 2026-07-24 [planwright] RESOLVED as load contention, not a code or platform bug — recorded because the false signal cost real diagnostic time and the fleet will keep producing it. During guard-coverage Task 6, tests/test-fleet-throttle.sh and tests/test-fleet-tower-watchdog.sh both failed locally (throttle on the assertion "the same excerpt after elapse is a fresh event and must re-engage"). Both pass in CI, and when re-run on an idle machine both pass locally too: throttle passes on a pristine origin/main extract (36 verdicts, exit 0) AND on the task branch (36 verdicts), watchdog passes on the branch (32 verdicts). The files are byte-identical across main and the branch (sha 69473d36), so the branch was never implicated. Cause: a concurrent sibling worker (worktrees/task-2) was running its own full suite on the same box, load average 12-31; the same pass clocked test-fleet-usage-gate.sh at 902s against 11.9s in CI (75x). Both files assert on elapsed wall-clock inside bounded windows, which is what CPU starvation breaks. TWO REAL FOLLOW-UPS. (1) Fleet-level: two workers running full suites concurrently on one machine corrupt each other's timings and manufacture spurious failures for both; consider serializing suite runs across workers, or a lock. (2) Test-level: these two files could assert on monotonic elapsed time with generous bounds, or skip under detected high load, so they degrade honestly instead of failing red on a busy dev box. An earlier version of this entry claimed a reproducible macOS-only failure and guessed at a BSD date parse; both were wrong and are retracted.
