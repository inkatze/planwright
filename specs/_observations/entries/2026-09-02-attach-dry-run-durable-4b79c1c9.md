- 2026-09-02 [planwright] fleet-dispatch-worktree.sh --attach-dry-run is dry only in its attach half: it still creates the branch and the worktree as durable side effects. A tower probing the dispatch shape before taking the per-spec lock therefore writes the first durable act outside the locked window. Observed 2026-09-02 on release-hardening/9. Either rename the flag to say what stays live, or add a fully-inert plan mode. ESCALATED TO DATA LOSS the same session. A tower used --attach-dry-run precisely to TEST whether a dispatch would collide on the shared task-<id> worktree path, treating it as a safe probe. It was not: the flag performed the switch, moving .claude/worktrees/task-3 from model-allocation/task-3 to fleet-lifecycle-closure/task-3 and OVERWRITING 595 uncommitted insertions across 9 files belonging to a live worker running in that directory. The changes were unstaged, so they were not in the object store: no stash, no dangling blob, no reflog entry, unrecoverable by git. Only the branch commit survived. Two compounding factors made this worse than the earlier benign case: the flag reads as a no-op so it invites exactly this probing use, and the helper performs no check that the target worktree is occupied by a different branch before switching it. A dry-run flag that mutates shared state is a trap that catches the careful user specifically -- the person who thought to check first is the one who gets bitten. Minimum fixes, both required: --attach-dry-run must be genuinely inert (print the plan, touch nothing), and dispatch must refuse outright when .claude/worktrees/<suffix> exists on a different branch, rather than silently re-pointing it.
