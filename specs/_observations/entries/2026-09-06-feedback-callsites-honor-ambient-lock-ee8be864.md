- 2026-09-06 [planwright] Both fence and liveness terminal-state call sites honor PLANWRIGHT_ALLOC_LOCK_HELD out of the AMBIENT environment when it string-equals the unit (scripts/fleet-fence.sh report_terminal_feedback, scripts/fleet-liveness.sh crash-record disable arm). allocation-feedback.sh then returns from take_unit_lock without acquiring, and runs health, mark-check, derive, obs-record and the ledger append entirely unlocked, which is the only way two concurrent terminal reports of one unit can both record. Neither call site ever holds that lock, and the only in-repo producers set it as a single-command prefix assignment rather than an export, so the honoring branch is dead in practice and, when reached, is a fail-open bypass of the mutual exclusion the once-per-unit guard depends on. The liveness site's own comment already asserts the safe behaviour (the inherited-hold variable is cleared, since anything reaching here came from an ancestor and would suppress a real acquire) and the code contradicts it. Proposed: unset unconditionally at both sites and delete the equality branch. Not applied here because it changes serialization semantics in concurrency-sensitive code and wants sign-off.
