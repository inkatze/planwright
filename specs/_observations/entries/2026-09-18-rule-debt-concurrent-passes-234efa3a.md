- 2026-09-18 [planwright] The settle-by-rule route writes rule.debt before the fleet lock, and rule_debt_drop removes every line for an item, so two settle passes on one surface (two towers, or a hook beside a manual run; nothing excludes them) can race: a pass that lost the claim drops the winner's debt line, and a put_file rewrite can lose a concurrent append. The loss costs something only when the winning pass then dies before its settling record commits, which is exactly the gap the debt file exists to bridge. Worth either holding the fleet lock for the debt write (the channel is not running then, so nothing nests) or tagging each line with the writing run so a drop takes only its own.
