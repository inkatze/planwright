- 2026-09-18 [planwright] The away push pays one event-log re-exec per item, on top of one notify fork per item, all outside the fleet lock. Measured on a fixture with every item blocking and every item due a first push: 10 items = 1.9s wall for the away `next`, 200 items = 34.7s. The settling pass lock hold is unmoved by it (0.047s at 10, 0.055s at 200, against the 2s stated bound), because none of that work is inside the critical section. The per-item cost is the same per-line publish path the open threads on PR #471 raise for the settling pass: `log_event` re-execs tower-queue.sh, which retakes the fleet lock for its own append, so N lines is N round-trips. Bounded in practice (an item pushes at most twice ever, so a steady tower loop pushes 0-1 per pass and only a cold start with many simultaneously-blocked workers pays the tail), but the same batched-publish fix would cover both callers.
