- 2026-09-06 [planwright] The two terminal-state call sites disagree about --obs-dir in three ways. scripts/fleet-fence.sh roots a relative value at the checkout and refuses one containing .., but the refusal returns 0, so gc still retires the fences and merely warns, while every other hostile-input refusal in that script exits 2; it is also the only one of the three new flags never validated during argument parsing, and it carries no length, control-byte or leading-hyphen grammar the way --alloc-key and --obs-scope do. scripts/fleet-liveness.sh has no .. check at all (absolute-only), so /a/b/../../../etc passes there, and its refusals ARE fatal. And the fence comment calling the .. ban the one escape that rooting cannot stop overstates it: obs-record.sh refuses only a symlinked final store and a symlinked entries dir, so a relative value traversing an intermediate symlink inside the checkout still resolves outside it. Proposed: move the check to parse time, make it exit 2 in the fence to match the sibling, give the value the same grammar the other two flags get, and either walk for symlinks or stop describing the .. ban as containment. Not applied here because it changes refusal semantics and exit codes on a path other callers branch on.
