Root cause: under claude -p with stream-json over a fifo there is no scheduler and no background-task notification delivery, so the workers own stated strategy ("The monitor will notify me when the suite verdict lands. Rather than poll...") is a dead end. Recovery was three hand-built relay messages written directly into in.fifo; fleet-streamjson.sh recover refused (correctly) because the worker process was still alive, and recover sends no prompt by design ("steering arrives later through the fifo") while NO sanctioned command exists to send that steering for this backend - only answer, for control_requests. What fixed it was relay wording that named the constraint explicitly and forbade yielding. Two implications: (a) the backend capability contract advertises steer but ships no steer command for this rung; (b) dispatch prompts for this backend should forbid waiting on notifications and require synchronous polling.
