- 2026-09-04 [planwright] The symlink lock owner token only protects in-process releases. fleet-state.sh lock prints no token and unlock accepts none, so the seven external consumers release unconditionally and a holder returning after its lock was broken still deletes the successor lock. allocation-ledger.sh already prints the token on lock and checks it on unlock; bringing the family to that shape is an API change to every consumer, so it was left out of the symlink-lock branch rather than made unilaterally.
