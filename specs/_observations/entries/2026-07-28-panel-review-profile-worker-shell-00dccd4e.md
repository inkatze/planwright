- 2026-07-28 [planwright] skill-drift(panel-review): the repo-profile signal cannot resolve inside a dispatched worker. /panel-review keys its backend default on PANEL_REVIEW_PROFILE (work -> codex, anything else -> personal -> gemini), but that is documented as a fish universal variable / shell rc export, which does NOT propagate into a non-interactive stream-json worker shell. So EVERY dispatched panel pass resolves to personal/gemini regardless of the host, and on a work machine where only codex is authenticated the pre-flight would stop with a gemini auth message and strand the pass. Hit on the PR #328 review gauntlet; worked around by using the authenticated codex (the documented work-profile backend) and recording the deviation. Follow-up options: have the profile resolve from a tracked-but-machine-local file the worker can read (planwright.local.yml or mise.local.toml, per the machine-local environment layer convention) rather than a shell variable; or have the pre-flight fall back to any authenticated backend in the supported set before stopping, surfacing the substitution. Keep the stop-rather-than-silently-drop rule; the gap is the SIGNAL being unreadable in the worker, not the backend policy.
