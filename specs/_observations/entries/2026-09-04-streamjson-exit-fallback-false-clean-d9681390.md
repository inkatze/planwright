- 2026-09-04 [planwright] The is_error fix closes the result-frame path to a false completion but not the neighbouring one. fleet-streamjson.sh writes the `exit <rc> <epoch>` fallback record only when no result record exists, so an API failure that kills the run BEFORE any result frame is emitted, on a worker that then exits 0 (the observed 529 shape: empty stderr, exit 0), records `exit 0`. Both readers treat that as a clean completion: status renders `completed exit=0`, read_completion sets completion_ok=1, and the detector classifies finished-but-unreaped against a clean tree — the same false-done, reached one path over. The fallback record has no is_error column and nothing else in the runtime dir is consulted for one, so the failure is unrecoverable after the fact even though events.jsonl holds the assistant text that names it. Noticed 2026-09-04 reviewing the is_error fix on planwright/chore/streamjson-is-error; the fix itself is correct for the frame it covers.
