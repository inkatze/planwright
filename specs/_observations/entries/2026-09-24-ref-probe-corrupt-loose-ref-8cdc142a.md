- 2026-09-24 [planwright] git show-ref --verify exits 1 for both an absent ref and a loose ref file holding garbage, so a fail-closed ref probe (flight-id.sh resolve_bases) cannot tell corruption from absence with plumbing alone; a ref pointing at a missing object is caught (exit 128). If a corrupt ref store ever matters, the probe would need to stat the loose ref file under the common dir before trusting exit 1.
