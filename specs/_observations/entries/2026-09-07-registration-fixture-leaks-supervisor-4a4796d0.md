- 2026-09-07 [planwright] tests/test-fleet-registration.sh case c3 leaked ONE stream-json supervisor per run, permanently, and had done so for as long as the case has existed. The case launches `fleet-streamjson.sh launch w-c3` WITHOUT `--foreground`, so the supervisor detaches; the EXIT trap's pid sweep was supposed to close it, but its two globs (`$tmp/state*/*/pid` and `$tmp/sj-*/*/supervisor.pid`) match no path this file ever creates — `home()` puts every fleet home at `$tmp/fleet-<case>` and the streamjson rung writes `<home>/streamjson/<worker>/supervisor.pid`. The loop body therefore never executed once: a guard that could not fire, the session's dominant defect class, and the reason it went unnoticed is that a leaked process is invisible to every assertion in the file. The trap's `rm -rf "$tmp"` then unlinks the supervisor's `out.fifo` while it is reading, so it blocks in `anon_pipe_read` FOREVER holding a deleted state dir; it is unkillable by any later sweep because nothing records where it went. MEASURED 2026-09-07 on this machine: 252 such supervisors alive, 250 of them with their `/tmp` fixture directory already deleted, the oldest running 4 days 23 hours, every one in state S on a deleted fifo. That is real background load on a box whose test suite runs 12 parallel jobs, and it is a plausible contributor to the load-sensitive failures recorded repeatedly this session (obs on c12, the throttle elapse flake, and the "passes in isolation" family) — every one of those was diagnosed against a machine carrying a few hundred stray shells nobody knew about. Fix: correct the glob AND close the supervisor inside c3 with an assertion that it is gone, because only an in-case assertion fails when the sweep silently stops matching again. Control run: main's copy of the file leaks +1 per run, the fixed copy leaks 0. Worth knowing for whoever revisits the detached-launch rungs: there is still no supported verb for closing a detached stream-json worker on main (the `stop`/close verb is unmerged in PR 399), so a test that launches one has no choice but to reach for the recorded pid itself.
