- 2026-09-03 [planwright] check:cdpath (guard-coverage Task 10) ships with two known, documented limits that were judged out of scope rather than missed. (1) It checks that a top-level unset CDPATH is PRESENT, not that it precedes the cd substitution, so a file whose unset sits below its root derivation is functionally broken and passes; enforcing order was rejected because a substitution inside a function defined above a correctly-placed unset would false-positive. (2) The pattern match has no notion of shell quoting, so an inline trailing comment or a quoted literal containing a cd substitution (echo "see $(cd ..)") is a false positive; the file must then carry a real unset CDPATH to pass, which is a cargo-cult line the guard subsequently reads as evidence. Both would need a real shell parser to resolve properly. Surfaced during Task 10 execution (2026-09-03).
