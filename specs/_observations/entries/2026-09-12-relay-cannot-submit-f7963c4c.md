- 2026-09-12 [planwright] The sanctioned tmux relay (orchestrate-relay.sh relay-command, load-buffer + paste-buffer -d) delivers a message into the worker CLI but cannot submit it, and whether it submits depends on the message length. A short single-line relay lands at an empty prompt and its trailing newline submits it; the worker picks it up. A long multi-line relay is turned by the CLI into a collapsed "[Pasted text #1 +N lines]" placeholder, which does NOT submit, so the message sits in the input box unread and invisible to capture-pane observation beyond that one placeholder line. Two relays stacked this way on one worker during a real run and the worker sat idle with both queued. The tower may not press Enter (no send-keys impersonation, D-38), so there is no sanctioned completion of the relay path for anything longer than a line or two: the doctrine promises attributed relay as the coordination channel and the mechanism only delivers the short end of it. Either the relay contract should be documented as single-line-only, or the mechanism needs a submit path that is not impersonation (a worker-side inbox file the skill polls would do it).
