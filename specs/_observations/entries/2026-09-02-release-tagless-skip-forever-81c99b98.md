- 2026-09-02 [planwright] scripts/release-window-check.sh maps "no release tags found" to exit 1 (window open) rather than exit 2 (could not determine), and scripts/release-lib.sh rl_latest_release_tag discards git tag -l exit status, so a broken object store, unreadable refs, or an all-non-SemVer tag set is indistinguishable from a genuinely tagless repo. Under release-hardening Task 9 the release-please guard maps exit 1 to a green skip, so any of those states suppresses the release proposal on every run, silently and forever. For a genuinely tagless repo it is also a closed loop: publishing requires the version bump that the suppressed proposal would produce. Harmless for planwright today (43 v* tags) and out of Task 9 scope since the semantics belong to REQ-A/D-2, but adopters copying the workflow shape inherit it.
