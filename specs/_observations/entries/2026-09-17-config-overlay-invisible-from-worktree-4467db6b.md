- 2026-09-17 [planwright] A tower run from an in-repo worktree loses the whole machine-local config layer. From /home/inkatze/dev/planwright/.claude/worktrees/tower, resolve-overlay-root.sh machine-local returns that worktree own .claude/, which holds only the tracked planwright.yml (planwright.local.yml is gitignored, so it exists only in the primary checkout). Every machine-local value silently falls back to the repo-tracked or core value: fleet_max_parallel_units 2 -> 3, max_parallel_units 2 -> 3, review_sequence [polish, self-review] -> [self-review]. The bound is not a preference: its planwright.local.yml comment records it being dropped to 2 on 2026-09-12 after four workers plus a tower put the host at load average 58 and produced wrong CI verdicts on sound work. So the failure mode is a worktree-run tower dispatching 3 concurrent units against a host guard that says 2, with nothing on stdout to say the layer was not read. config-get.sh exits 0 either way. Candidate fixes: resolve the machine-local layer from the primary checkout (git rev-parse --git-common-dir) rather than the cwd, or have config-get warn when a layer root resolves to a directory with no layer file while a sibling checkout has one.
