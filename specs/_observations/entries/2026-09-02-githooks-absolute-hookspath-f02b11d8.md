- 2026-09-02 [planwright] A clone whose core.hooksPath was set to an ABSOLUTE path (e.g. /path/to/repo/githooks rather than the tracked relative `githooks`) fails check:githooks in every worktree, so `mise run check` cannot go green for any dispatched worker until someone runs scripts/wire-githooks.sh. CI is immune because ci.yml wires-then-verifies on a fresh clone, so the condition only ever bites local/dispatched runs and presents to a worker as an unrelated logic CI failure at the convergence gate. Surfaced during tower-front-door Task 1; remedied by the documented wire-githooks.sh run (idempotent, clone-global). Possible follow-ups for /spec-draft to weigh: have the worker/dispatch pre-flight assert the wiring the way CI does, or have check-githooks distinguish an absolute-path-to-this-clone value from a genuinely unwired clone in its message.
