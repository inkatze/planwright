- 2026-07-28 [planwright] The command guards' new awk screen cannot distinguish a REDIRECTING '>' (print > "f") from a RELATIONAL one ($1 > 5) without a real awk lexer: the character is identical and only its grammar position separates them, so the screen defers on any '>' and over-defers ordinary comparison filters. Fail-closed and no worse than the pre-fix state (where every awk invocation deferred), but it leaves the most common awk filter idiom prompting. A future spec could add a small awk lexer (track print/printf argument context) to allow the relational form; that is a parser, not a character screen, and belongs with the shared command-guard-lib extraction rather than bolted onto the duplicated engine.
