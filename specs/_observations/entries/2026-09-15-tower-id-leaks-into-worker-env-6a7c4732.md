- 2026-09-15 [planwright] A tower that exports PLANWRIGHT_TOWER_ID in the same shell that runs fleet-streamjson.sh launch leaks its own identity into the worker process, and from there into every test the worker runs. Observed 2026-09-15: the tower-comms task-2 worker had to add `env -u PLANWRIGHT_TOWER_ID -u PLANWRIGHT_TOWER_SESSION_ID` to its test harness because the inherited value overrode the identity each case meant to set. Launching without the export makes fleet-register warn `no tower identity available` instead, so neither shape is right: the launch wants the tower id passed as an argument (or scrubbed from the child env by the dispatch-env wrapper), not inherited.
