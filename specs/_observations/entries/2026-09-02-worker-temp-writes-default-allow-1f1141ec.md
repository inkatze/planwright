- 2026-09-02 [planwright] Operator decision 2026-09-02: a dispatched worker writing into a temp directory it creates itself (scratch fixtures, negative controls, throwaway repos under /tmp or the session scratchpad) should be auto-approved by default, not queued to the operator. Today worker-command-guard.sh queues any write outside the worktree, so benign scratch fixtures stall the unit and cost the operator a relay per occurrence; observed three times in one fleet wave on release-hardening/9 building a grep negative control. Wanted: a default-allow for self-created temp-dir writes, expressed as a configurable knob (e.g. worker_allow_temp_writes, default true) so an adopter with a stricter posture can turn it off. The allowance must stay bounded to paths the worker created under a temp root; it is not a general write-outside-worktree allowance, and rm targets outside such a self-created dir still queue.
