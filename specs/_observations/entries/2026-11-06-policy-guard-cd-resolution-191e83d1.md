- 2026-11-06 [planwright] policy-guard resolves a cd target as $eff/<arg> and reads it with git -C (physical), while bash resolves it logically and through CDPATH, and earlier non-git segments (ln -sfn, mv, rm) are not tracked as state changes. Review probes showed `cd <foreign>/lnk/.. && git merge ...`, a CDPATH assignment before a bare relative cd, and `ln -sfn <primary> lnk && cd lnk && git merge ...` all defer while bash lands in another checkout; the last merged a branch into a primary checkout's local main. Fix shape: resolve cd the way bash does (or refuse when logical and physical paths differ), treat a bare relative cd as unreadable, and refuse a git act after a filesystem-mutating segment.
