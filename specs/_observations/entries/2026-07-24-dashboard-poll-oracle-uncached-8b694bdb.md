- 2026-07-24 [planwright] Task 8 shipped the dashboard poller (fleet-dashboard.sh watch) and addressed half of the Task 7 polling observation (obs status-view-task8-perf): every page now carries a UTC generated-at stamp plus a self-refresh on the same interval, so a stale page — a dead writer loop, or a merge slower than the interval — reads as stale instead of quietly showing old state. The other half is still open and was deliberately left at the merge layer rather than papered over in the dashboard: each watch iteration re-runs the FULL fleet-status.sh merge, so the uncached claude-agents-json oracle probe (2-10s cold) and the per-worker streamjson status fan-out (~5-10 procs/worker) are paid every interval. At the 30s default that is a meaningful duty cycle on a large fleet, and it is why the interval floor is 1s but the useful floor is much higher. Caching belongs to the source readers (a cached-with-age oracle source line, a batched streamjson status --all), not to a renderer that is contractually forbidden from reading sources itself — putting a cache in fleet-dashboard.sh would have made it a second source-reading implementation in all but name, which is exactly what D-10/REQ-D1.2 forbid. Seed material for a merge-layer follow-up.
