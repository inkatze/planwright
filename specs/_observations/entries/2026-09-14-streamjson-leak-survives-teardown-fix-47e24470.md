- 2026-09-14 [planwright] The streamjson supervisor leak recurred on a branch that already carries the teardown fix. During one task twelve concurrent rounds of the lock suite left 47 processes looping against deleted /tmp sandboxes and 41 supervisor shells, driving load past 55 on an otherwise idle host and slowing the very gate the worker was waiting on. The teardown added earlier reaps what a suite run spawned, and it works for a run that completes; what it does not cover is a run killed or interrupted partway, and twelve concurrent copies of a suite that itself spawns supervisors produce exactly that. This is the fifth sweep of the same class in one session, each from a different direction: a crashed fleet run, the ordinary test suite, a worker exercising that suite, and now the suite under deliberate concurrency. The pattern across all five is that the reaper always belongs to the thing that spawned the process, so whenever that thing dies unexpectedly the reaping does not happen. Worth considering an owner that outlives the spawner - a sweep keyed on the sandbox root no longer existing, runnable from anywhere and safe to run at any time, rather than a teardown each spawner must reach.
