- 2026-10-03 [planwright] The tower skill's posture check at bring-up says to union user, project, local, managed, and any --settings file, but a session has no way to discover which --settings file it was launched with. In the documented launch (--settings <plugin>/config/tower-settings.json) the readable layers alone report every shipped deny entry as missing, so the check fails closed falsely; in a tower session on 2026-10-03 the session had to read its own process command line to find the layer. The check needs a discoverable source for the --settings layer (an environment variable or marker the launch sets, or a launcher that records the path), or should treat the shipped tower-settings file as the presumed layer when the launch is the documented one.
