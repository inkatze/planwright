- 2026-09-03 [planwright] Both PRs opened during the 2026-09-03 overnight fleet run reached "CI green, draft open" with zero external review passes against them: planwright#392 (0 reviews, 0 comments, check and window-lock passing) and dotfiles#122 (0 reviews, 0 comments, lint/services/skill-contracts/test-environments passing). Neither worker was at fault. review_sequence can only name skills resolvable under the plugin skills root, and panel-review and copilot-review ship as dotfiles-local commands, so the sequence cannot carry them (issue #393). They run only when the tower writes them into the unit prompt by hand, so the default path for a dispatched unit is to skip them. The cost is that a PR passing CI looks finished, and the standing instruction "flip it ready when all verifications pass" silently degrades into "flip it ready when CI passes" unless someone checks the review count first. Detection belongs at the ready-flip decision rather than in the dispatch prompt: `gh pr view <n> --json reviews,comments` returning zero of both, on a unit whose spec expects external review, is the signal. A second constraint surfaced while fixing this: a review worker cannot be dispatched into a repo where a sibling worker already holds the single working tree on a different branch, because the reviewer needs the PR branch checked out. In a worktree-per-unit repo that is free; in a plain checkout such as dotfiles, review passes serialize behind whatever else runs there. Related: allow-rules-miss-redirect-shapes.
