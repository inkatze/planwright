- 2026-09-03 [planwright] fleet-lifecycle-closure Task 4: fleet-streamjson.sh `stop` seeds its kill set from the pids recorded in supervisor.pid/worker.pid, filtered only by presence in the process table. Between a crash and the stop those files hold pids the worker no longer owns, so a pid reused by an unrelated process in that window would be SIGTERMed and then SIGKILLed by a verb whose whole premise (REQ-B1.3) is that it cannot over-match an operator process. The state-dir argv match covers the supervisor soundly and is reuse-proof; only the recorded worker pid carries the exposure, and only after the supervisor died without reaping it. The bundle already defers start-time-checked pid liveness to the supervisor-hardening bundle (tasks.md Deferred, obs:95ecef76 item 4), so this is not a new defect so much as a newly destructive consumer of a known one: before `stop`, a stale pid corrupted a status verdict; now it can receive a signal. Worth raising the priority of the start-time stamp when that hardening bundle is drafted, and worth noting that Task 5 (headless stop) and Task 6 (fleet-cleanup process) inherit the same seed path by design.
