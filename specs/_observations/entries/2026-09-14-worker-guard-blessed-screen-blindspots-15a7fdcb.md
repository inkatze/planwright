- 2026-09-14 [planwright] Replacing the worker-guard awk lexer with a positively-blessed screen (reject everything; recover | only as || or inside a regex opened where awk cannot divide) closed all four known bypasses, but the first draft of the REPLACEMENT still had two live arbitrary-exec holes, both from the same root: the blessing character was read out of text awk does not execute. A { ; & inside a STRING blessed the next / ({x = "&" /2; print s | c; y=1/2} runs sh), and a backslash-newline continuation made the newline look like a statement end ({x = 1 \<NL>/ 2; print s | c; y = 1/3} runs sh). Lesson: positive blessing is only as sound as the context the deciding character is read from - a screen with no tokenizer still has to skip strings and continuations, or its whitelist is decided by attacker-supplied text.
