- 2026-09-03 [planwright] fleet-lifecycle-closure Task 4: journal_close distinguishes three awk outcomes - 0 pending rows found, 1 none found, anything else could not read the journal - and the distinction is load-bearing, since folding the read failure into the no-rows case clears the attention row while every receipt stays pending. Reproduced on this host: for a file that cannot be opened, mawk and the default awk exit 2 but busybox awk exits 1, so on busybox the unreadable journal is indistinguishable from an empty one and the close reports success over receipts it never settled. The script header explicitly claims the busybox bar, and the same case-$?-in idiom over an awk or helper exit appears in inception-validate.sh, check-anchor-freshness.sh, release-pending.sh and release-window-check.sh, so the portability question is repo-wide rather than local to this verb. The portable discipline is to test readability separately from the awk verdict rather than to read a specific non-zero code as the error channel.
