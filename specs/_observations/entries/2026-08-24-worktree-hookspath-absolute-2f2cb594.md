- 2026-08-24 [planwright] This clone has core.hooksPath set to an ABSOLUTE path into the primary checkout, so every worktree runs the primary checkout branch hooks rather than its own, and check:githooks fails in every worktree (it requires the literal relative `githooks`). The absolute spelling also breaks the D-3 property that a checkout predating the hooks runs its own older hook: a Task 3 commit-msg screen would fail closed against a branch that has no scanner. Remedy is scripts/wire-githooks.sh, but nothing detects the absolute-path state until someone runs the aggregate inside a worktree.
