- 2026-09-12 [planwright] scan:secrets runs `gitleaks detect --source .`, which walks every ref in the object store rather than the checked-out branch. Worktrees share that store, so a secret-shaped test fixture committed on one worker branch turns every sibling worktree red on a leak it did not introduce and cannot fix locally - the remedy lives on someone else branch. Verified: commit f7c99d5 is reachable only from planwright/tower-comms/task-1, yet the scan found it from the operator-dialogue/task-10 worktree. One worker parked itself over this; a fleet run retried against it until it fell over. The sanctioned fix (a .gitleaksignore fingerprint, since history is never rewritten) works but is only effective once it reaches main, so the window between a fixture landing on a branch and its ignore entry merging is one where the whole fleet gate is red. Worth considering whether the scan should be scoped to the branch under test.
