- 2026-09-12 [planwright] fleet-cleanup.sh worktree refuses every removal it cannot prove safe, and its two proof paths both fail on the repository's own normal history, so in practice it refuses almost everything. Path one: with no --merged-pr it demands an upstream, which a branch carrying ZERO commits can never satisfy - there is nothing to push, so nothing can prove it pushed, and four empty leftover worktrees were unremovable. Path two: with --merged-pr it compares the worktree tip to the PR head SHA by EQUALITY, so a tip that is a strict ANCESTOR of the merged commit (the worker pushed more after the local ref went stale) reads as "holds commits that PR did not carry" and is refused, even though containment is exactly what ancestry proves. Separately, git cherry is useless as a landed-ness test here because every PR is squash-merged: no individual patch-id survives on main, so cherry reports every commit of a fully merged branch as unmerged. The tests that actually work are (a) zero commits ahead of origin/main for the empty case and (b) git merge-base --is-ancestor <tip> <pr-head-oid> for the merged case. Both gaps push an operator toward bypassing the guard entirely, which is the worst outcome for a guard whose whole purpose is to stop an unrecoverable removal.
