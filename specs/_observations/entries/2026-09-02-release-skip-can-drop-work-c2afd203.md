Two gaps found while executing release-hardening Task 9. First, the lock blocks nothing server-side: the same bundle D-11 verified this repo has no branch protection and no required status check, so release-window.yml goes red on main without preventing a merge. Second, an ordering hole the lock could not close even if enforced: a feat commit A merging before the standing release PR B triggers a release-please run whose guard step executes after B merged, so the guard sees an open window and skips, and A is never folded into a regenerated release PR. Publishing the tag also runs no ci workflow (a tag push matches neither push branches main nor pull_request), so nothing re-triggers the proposal until the next unrelated commit lands. Candidate mitigations: a workflow_dispatch trigger for manual recovery, or a re-check after the proposal step that fails the job when the window opened mid-run.
