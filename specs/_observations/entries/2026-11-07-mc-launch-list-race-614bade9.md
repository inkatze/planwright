- 2026-11-07 [planwright] mission-control-launch.sh list (cmd_list) checks a registry row with [ -f ] and then dies with exit 2 on [ -r ] failing, so a row a concurrent retire or a refused launch's rollback unlinks between the two tests aborts the whole listing instead of skipping that row. Its callers then diverge: mc-config.sh doctor reports an unknown launches check, mc-handover.sh's announce treats the failed listing as empty and silently reaches no session, and mc-keeper.sh's next verb fails while its sweep and pending-prompt reads degrade. The same function reads each row field by field, opening the file once per field, so a row unlinked partway prints with empty fields and exit 0 (doctor now reports such a row as naming no known rung), and it skips a row in another format with only a stderr line, which every caller discards, so a session a newer or older launcher registered is invisible to them. Likely fix: read each row once, skip a row that no longer exists, die only on one that exists but cannot be read, and give callers a way to learn that rows were skipped. Seen while reviewing the doctor audit; not changed on that branch.
