- 2026-07-26 [planwright] The repo lints .github/ with yamllint only, which checks YAML syntax and style but nothing about GitHub Actions semantics — so a whole class of workflow defects ships unguarded. Concrete instance found reviewing guard-coverage Task 6: a `run:` step without an explicit `shell:` gets `bash -e {0}`, NOT `bash -eo pipefail`, so `cmd | tee report.txt` reports the pipeline as green even when cmd exits non-zero (verified against the current workflow-syntax docs and reproduced locally: `bash -e -c "false | tee /dev/null"` exits 0, the `-eo pipefail` form exits 1). test-timing.yml pipes measure-test-time.sh into tee, and that script deliberately exits 1 on a failed test file so "a broken suite never measures into a clean-looking baseline" — the pipe silently defeats that contract. actionlint would catch neither the pipefail case specifically nor much of this class on its own, so the candidate guards are: adopt actionlint for expression/context/deprecated-input errors, plus a small house check that every `run:` step containing a pipe either declares `shell: bash` or sets pipefail. Fits the guard-coverage REQ-H catalog family.
