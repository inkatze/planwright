- 2026-11-15 [planwright] (hub, under r-14, an upstream gap) Release-please PRs never start CI in an adopter repo: the release workflow pushes the release PR's branch with GITHUB_TOKEN, GitHub does not trigger workflows from GITHUB_TOKEN pushes, and every CI run on the release PR comes back action_required. Seen on planwright's own release PRs and on an adopter repository. Recommended fix: planwright's release workflow template documents and uses a GitHub App token or a fine-grained token for release-please, and planwright's setup check names the gap when a repo's release workflow still uses GITHUB_TOKEN; any such token lives in the operator's secret manager and the repo's Actions secrets, never in a file in the repo. For planwright itself that crosses a recorded choice: .github/workflows/release-please.yml uses the default GITHUB_TOKEN on purpose, under autopilot-reflex's zero-CI-secrets posture, so the fix there needs that decision revisited.
