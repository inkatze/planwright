- 2026-08-24 [planwright] The header-block declaration parse (spec_parse_header_value / spec_parse_header_block) is deliberately the one spec-bundle parse that does not consume the shared fence lexer, and doctrine does not say so. It needs no fence guard because a column-0 fence line is neither blank, an H1, nor a header line, so it ENDS the header block. That is consistent with the header-block extent rule as written, but it produces a different outcome from every other parser: a fenced example placed ABOVE the real header lines does not hide them as illustration, it truncates the block so the real declaration reads as MISSING. Fail-closed, so not a bug, but the interaction between the Fenced illustration rule (universal) and the header-block extent rule (positional) is currently only discoverable by reading spec-parse.sh. Worth one sentence in doctrine/spec-format.md naming which rule wins.
