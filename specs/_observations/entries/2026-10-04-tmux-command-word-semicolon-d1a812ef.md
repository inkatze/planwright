- 2026-10-04 [planwright] A private-socket tmux 3.6 probe (fleet-hardening Task 11, 2026-10-04) shows the command words after 'new-session --' do NOT always reach the process verbatim: tmux splits its argv into commands before option parsing, so any word ENDING in ';' ends the command there (the ';' is dropped and the next word is parsed as a new tmux command, failing the whole invocation as 'unknown command' when it is not one), while a trailing '\;' is unescaped to a literal ';'. A lone ';' word also separates. This contradicts the kickoff's 'tmux 3.6 command-word probe' Source, which grounds D-12's decision to apply no charset to command words: a forwarded launch flag or prompt word ending in ';' (for example a brief path or prompt sentence) would truncate the worker's argv or refuse the launch. The detached launch Task 12 builds needs either a rule for such words (refuse, or escape a trailing ';' as '\;') or an amended D-12; the Task 11 stub tmux now models this parsing so a fixture can show it.
