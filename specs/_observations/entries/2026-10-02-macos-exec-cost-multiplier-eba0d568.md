- 2026-10-02 [planwright] Owner: universal-binary (input to its macOS bake-off measurements; surfaced by the test-throughput slow-test profile). On the operator's macOS host a process exec costs 14.7-16.7 ms from a fleet worker session against 0.7 ms on the GitHub Linux runner (a fork without exec: 0.8 ms against 0.28 ms), and each exec costs about 13-14 ms of opendirectoryd CPU, even for /usr/bin/true: opendirectoryd runs near 80% of a core during an exec loop against 0.3-0.7% of a core idle. Because that daemon is one process, it serializes execs machine-wide: the parallel full run (15 jobs) took each slowest-half file 4.9-17.3x its serial time (median about 12x), and each file's serial run is 2.7-8.9x its own mean serial CI time (paired per file, not across ranges). The same launches from an attended terminal cost about 4 ms, so the amplification is tied to the session's process tree. These factors describe this one host, measured from a fleet-worker session, for the slowest-half files; they are not a general Linux-to-macOS conversion. The cost scales with a script's exec count rather than its fork count, so a bake-off should measure on macOS, from the session type that will run it, rather than scale a Linux number.
