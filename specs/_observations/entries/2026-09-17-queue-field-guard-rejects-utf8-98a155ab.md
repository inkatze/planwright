- 2026-09-17 [planwright] tower-queue.sh rejects legitimate non-ASCII text because its field guard filters UTF-8 continuation bytes as if they were C1 control characters. The guard on origin/main (scripts/tower-queue.sh, the field-grammar check around line 1036) reads: [ "$(printf %s "$val" | tr -d \\000-\\037\\177\\200-\\237)" != "$val" ] and errors with "refusing field <key>: the value carries a control byte (flatten the text first)". The intent, per the field-grammar comment, is "no C0 or C1 control byte and no DEL". The bug is the \\200-\\237 range: in UTF-8 the bytes 0x80-0x9F are CONTINUATION bytes, never characters in their own right, while a real C1 control encodes as the two-byte sequence 0xC2 0x80 through 0xC2 0x9F. So the check flags any text whose encoding happens to contain a byte in that range and lets other non-ASCII through. Measured directly: an em dash U+2014 (e2 80 94) is REJECTED, a smart quote U+2018/U+2019 (e2 80 98 / e2 80 99) and an ellipsis U+2026 (e2 80 a6) are in the same family and reject for the same reason, while CJK U+4E2D (e4 b8 ad) and e-acute U+00E9 (c3 a9) are accepted, and a real C1 U+0085 (c2 85) is caught only incidentally, via its second byte landing in the stripped range. The practical blast radius is any operator turn or worker text containing a pasted smart quote, em dash or ellipsis, which is common. How it surfaced: PR #468 (tower-comms task 2) was green in CI before a forward-merge of origin/main and failed immediately after, on tests/test-tower-loop-log.sh case "multibyte delivered", where the loop log caps a turn at 4095 bytes on a character boundary and hands it to the queue, which then refuses it. Neither task is at fault: the guard arrived on main with PR #467 (task 3) and task 2 is simply the first caller to pass it multibyte text, so the two were each green in isolation and incompatible once merged. Fix shape: keep the byte-wise test for C0 (\\000-\\037) and DEL (\\177), and detect C1 as the two-byte UTF-8 sequence \\302\\200-\\302\\237 rather than stripping raw 0x80-0x9F; add a fixture covering an em dash, a smart quote and a real C1 so the distinction is pinned. Operator decision 2026-09-17: this lands as its own unit rather than inside the task-2 PR, and PR #468 stays merge-blocked until it does.
