- 2026-09-03 [planwright] fleet-lifecycle-closure Task 4: every single-initiator election in the fleet scripts (journal.lock, recover.lock, launch.lock, and fleet-state.sh's store lock) rests on mkdir being atomic, which is a POSIX guarantee but not a universal fact of the installed tool. uutils coreutils 0.8.0 — the /usr/bin/mkdir on images that symlink coreutils to the Rust reimplementation, including this dev host — returns success to several concurrent creators of one path roughly 20% of the time at 8-way contention; its sequential EEXIST is correct (rc=1), so only contention exposes it, and busybox mkdir plus a raw os.mkdir both hold at 0 failures over the same races on the same filesystems. The visible symptom is test-fleet-streamjson.sh c25b failing with two or three concurrent launches all reporting 'launched': the election is lost underneath the script, not inside it, and the same host would let two real towers double-launch one worker. c25b now probes mkdir under contention and skips out loud rather than reporting a defect the code does not have. Worth knowing before trusting any lock-election test result on an unfamiliar host, and worth weighing if planwright ever needs an election that survives a non-atomic mkdir.
