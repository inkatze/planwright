- 2026-09-12 [planwright] Claude Code 2.1.269 consumes the literal braced token ${CLAUDE_PLUGIN_ROOT} in a hook command as a plugin-context substitution. Supplied through a --settings fragment there is no plugin context, so it substitutes EMPTY and config/worker-settings.json wires its auto-approve hook to ""/scripts/worker-command-guard.sh, which never runs - so every dispatched worker prompts on every routine command. Measured 2x2 on this machine: "${CLAUDE_PLUGIN_ROOT}"/x NOT expanded; $CLAUDE_PLUGIN_ROOT/x expanded; "${OTHER_VAR}"/x expanded; ${OTHER_VAR}/x expanded. Hooks ARE loaded from a --settings fragment (verified with a probe hook that wrote a marker); only the braced plugin-root spelling fails. Landmine-free fix: fleet-dispatch-env.sh exports a self-located CLAUDE_PLUGIN_ROOT from dirname $0/.., the fragment uses the bare $CLAUDE_PLUGIN_ROOT spelling, and fleet-streamjson.sh pins --settings at its own config/worker-settings.json. No symlink, no version pin, no manual merge. Empirical CLI behaviour rather than documented contract, so it wants a pinning test.
