- 2026-07-27 [planwright] Precise root causes for the worker-command-guard.sh permission flooding that worker-command-guard-compound-forms (2026-07-21) attributed to "the literal-path matcher". Measured against v0.32.0 by probing the hook directly; compound forms, pipes and && are NOT the problem (ls|wc, ls&&echo, ls|grep|cut|tr|head all ALLOW). Three real causes: (1) ANY "[" in a sed script defers wholesale -- an explicit documented bail because bracket-expression parsing across sed dialects is error-prone -- so sed -E s/a{2}// ALLOWS but sed -E s/[0-9]// DEFERS; (2) awk is entirely unverified, so even awk /x/ and awk {print 1} defer; (3) a plugin-script path (<plugin-root>/scripts/*.sh) defers, currently worked around per-machine with a version-pinned Bash allow entry that breaks on every plugin update. Sharpest consequence: the backlog-grep planwright own runbook prescribes in every dispatch prompt -- ls specs/_observations/entries/ | sed -E s/^[0-9-]{11}//... -- contains a bracket expression, so the shipped guard cannot approve the command our own standing instructions require. Candidate narrower screens: for sed, defer on the w/r/e commands and -i/--in-place rather than on regex content (bracket expressions in s/// and addresses are read-only however they parse); for awk, defer on system(), print/printf redirection, close(), and -f progfile, allow the rest; for plugin scripts, have the guard resolve the planwright root itself (PLANWRIGHT_ROOT then CLAUDE_PLUGIN_ROOT then <claude-dir>/planwright) and allow <root>/scripts/*.sh, which removes the per-machine version-pinned entry entirely. Owner is worker-permission-ergonomics (Task 1 built the hook, Task 2 wired it; all tasks complete, so this needs a spec amendment). See also command-guard-engine-dup: any tokenizer change must currently be applied twice, to worker- and tower-command-guard.
