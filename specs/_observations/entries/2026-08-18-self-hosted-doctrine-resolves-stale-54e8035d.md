- 2026-08-18 [planwright] When planwright executes its own specs, the doctrine resolution chain reaches the INSTALLED plugin copy, not the repo under development. On this run the resolved doctrine was the 0.31.0 plugin cache while the checkout was 0.33.0, and the resolved doctrine/spec-format.md did not contain the Task 1 amendments the unit was implementing against — the contract lived only in the checkout. Neither PLANWRIGHT_ROOT nor CLAUDE_PLUGIN_ROOT is exported into a skill Bash subshell here, so resolution falls to the self-location arm under the plugin cache; the repo-tracked doctrine overlay (.claude/doctrine/) is empty, so nothing pulls it back. Nothing broke, because the work read the checkout doctrine and only the procedure read the resolved copy, but a skill that reads a resolved doc to decide behavior would silently run a release-old rule against a newer contract. Candidate fixes: a self-hosting arm that prefers the checkout doctrine/ when the checkout IS planwright, or a loud one-line provenance notice naming the resolved layer and version at run start.
