- 2026-11-05 [planwright] A shared scratch root was emptied under live sessions. Every stream-json session mission control launches with its working directory at the primary checkout gets the same TMPDIR, the scratch root keyed to that checkout (<fleet home>/scratch/<sha1 of the checkout path>). In the scripts the primary checkout was running (it was behind main), a session's final close (fleet-streamjson.sh stop --final, which every retire and launch rollback makes) removes the scratch root it recorded outright, with no check for other sessions using it, so retiring any one primary-checkout session deletes every other one's temp files, including another live session's working folder. Seen twice in one day (about 09:29 during a batch of closes, and about 09:55 as two sessions launched from the primary were retired while a new one started). The cause is not Claude Code's own startup cleanup and not the scratch-root setup (worker-session-record.sh --scratch keeps an existing root; only --fresh-scratch empties, and only the tmux launch of a just-created worktree passes it). Already fixed on main by the change that gives each stream-json session its own scratch root inside the worktree's and leaves a worktree-wide root another worker records in place (pull request 841); the remedy is to bring the primary checkout's scripts up to main, and a session launched before that keeps the shared root until relaunched. Follow-up worth considering: mission-control-launch.sh could refuse or warn when the scripts it runs are older than the installed release, since launches run the primary checkout's copies.
