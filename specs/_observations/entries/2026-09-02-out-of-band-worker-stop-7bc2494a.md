- 2026-09-02 [planwright] A tower had to SIGTERM a dispatched worker directly on 2026-09-02 because no sanctioned stop exists. fleet-streamjson.sh is launch|answer|recover|alarm-scan|status: there is no stop, kill, reap, or teardown verb, which is the exact gap fleet-lifecycle-closure was written to close. The trigger was the worktree-suffix collision recorded in worktree-suffix-collision: dispatching model-allocation task 3 displaced the still-live fleet-lifecycle-closure task 3 worker off its worktree, leaving a process alive whose working directory now belonged to a different spec branch and which could have committed across specs. Its own deliverable was already complete and pushed (PR #387), so ending it was safe, and the operator authorized the kill. Two things this exposes beyond the missing verb. First, killing by pid bypasses whatever teardown the backend would want to do: no marker clear, no attention-store clear, no registry deregistration, no observation carry from the dying worker; the tower must remember to do each by hand and nothing checks that it did. Second, the reconcile sweep will now see positive evidence of death and can orphan the unit correctly, but only because the kill was observed by the same session that performed it: a kill by any other actor would look identical to a crash, and the sweep would park a unit whose work is actually finished and merged-ready. The stop verb needs to distinguish completed-and-stopped from died-mid-flight, which a bare signal cannot. Ironically the task that would supply the verb (fleet-lifecycle-closure Task 4, stop on fleet-streamjson.sh) is blocked behind Task 3 -- the very unit whose worker this was.
