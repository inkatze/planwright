- 2026-08-24 [planwright] The execution freshness gate compares a recorded anchor against a recompute, but the anchor COMPUTER version is a hidden input to that comparison and nothing in the gate names it. On the anchor-integrity 2+3 branch the /execute-task pre-flight gate reported a mismatch for specs/anchor-integrity itself (recorded 48504616, recomputed efb06305) even though the bundle content was byte-identical to its sign-off commit and to origin/main: dispatch-fetch.sh re-points the ref but runs the LOCAL scripts/spec-anchor.sh, which on this branch already carried Task 2 hash-scope change. The prescribed remedy for a mismatch is a /spec-kickoff delta re-walkthrough, which is exactly wrong here (there is no content delta to re-walk) and would have blocked the task whose entire job is to write the machine re-anchor entry that repairs it. Any branch that changes the anchor computer will false-halt its own dispatch the same way. Candidate fixes: have the gate compute BOTH the ref anchor and the ref-script anchor and report a computer-version divergence distinctly from a content divergence; or an explicit meta-spec carve-out naming the self-changing-computer case and its remedy (proceed and land the sweep) alongside the existing halt list.
