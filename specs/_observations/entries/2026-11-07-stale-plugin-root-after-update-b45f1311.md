- 2026-11-07 [planwright] After a plugin update, long-lived workers and the subagents they spawn keep PLANWRIGHT_ROOT and CLAUDE_PLUGIN_ROOT pointing at the old version directory (still on disk in the plugin cache), so they run old scripts and old doctrine against a repository that expects the new one, and the skew is silent: this host saw sessions on 0.69.0 after 0.70.0 installed. Related but distinct from obs:217cc262, which is the worker-settings generator and the running skill disagreeing at dispatch; this is the env roots going stale inside an already-launched session or inherited by its children. Suggested permanent fix in planwright's shipped launcher and scripts: the launcher exports the roots resolved from the installed plugin record at each launch (never inherited from a parent session), and the scripts (resolve-rule-doc.sh, step-run.sh, the dispatch helpers) compare an inherited root's version to the installed one and either refresh to the installed root or refuse with a message naming both versions. Reported from the operator's work machine, also seen on this host.
