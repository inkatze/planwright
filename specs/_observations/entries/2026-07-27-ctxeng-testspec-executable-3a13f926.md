So the spec points at the suite but the suite is not the spec, and a test-spec entry can name a test file that was renamed or deleted with the bundle still validating clean (obs:34edff2a is the prose-drift instance of exactly this, where the test-spec verification scope diverged from requirements and from the shipped test, caught only by a human review pass). The Claude-5 references-over-prose guidance argues the other direction: the detailed test suite can BE the spec. Change: allow a [test]-tagged entry to carry an optional machine-resolvable reference (tests/test-foo.sh plus a case name, or a tagged bats id) and have spec-validate assert the file exists, optionally that the case name is present. Risk: the check must key strictly off the tag - [manual] and [design-level] entries have no runnable target by design, and requiring one would either break them or push authors to mistag, so the rule is "if you claim [test], name something resolvable", never "every REQ must name a test".
