- 2026-11-05 [planwright] Mission control first run, adopter layer rendered by another tool: a bootstrap deadlock. The first-run add correctly refuses to write a layer another tool renders (exit 4, one handover-operator line per key to add at that tool's source), but the only way mission control starts a session is mission-control-launch.sh, which needs a configured program, and the program is exactly what the refused write would have configured. So mission control cannot launch a session into the repository that renders the layer (for example a dotfiles configuration-management role), and the first run has no path except the operator editing that source by hand. Seen on a second machine running planwright 0.66.0. Not fixed in the flight that recorded it, because every launch is defined per configured program (rules rendered from the program's store, the program's cadence in the brief, its owner and registry row, the program's repositories for the worktree), so a launch before any program exists needs a spec amendment to mission-control. Concrete proposal for that amendment: (1) a bootstrap launch, mission-control-launch.sh launch --bootstrap --cwd <rendering repository>, allowed only while mc-config.sh entry says first-run, scoped to the one repository the operator names as the renderer (mission control cannot infer it from the layer header), kind worker, no program rules, the rendering repository's own configured cadence, owner mission-control:bootstrap, retired when its pull request merges or closes; (2) its brief composed from the handover-operator lines verbatim (each key: value to add at the source), so the session lands them as a draft pull request in that repository; (3) after the operator merges it and re-renders the layer, the first run re-reads the layer and resumes (mc-config.sh add then refuses as already configured, or entry says resume). Simpler fallback if the launch mode is refused: on exit 4, have add also print a ready hand-off brief the operator can paste into a session they open in the rendering repository.
