- 2026-09-02 [planwright] The [pending-sign-off] mechanism is sound but illegible at the moment of decision. Four specific confusions, surfaced 2026-09-02 when the repo author could not say whether they should approve their own branch's marked items. (1) The approval act is invisible: gate-wiring defines it as "the draft->ready flip with the commit still present is the approval", so approving is expressed by NOT doing something plus a status change that looks like a status change. Nothing at flip time announces that flipping approves PS-1..PS-N, so a human flipping for an unrelated reason (CI green, ready to share) silently approves every marked finding. (2) The marker name implies clearable state it does not have: [pending-sign-off] reads like a flag cleared on approval, but history is never rewritten, so the subject says "pending" forever and only the PR draft status ever changes. (3) The checklist checkbox is a decoy: the doctrine says it "is a reading aid for review progress, not the approval", yet it is visually indistinguishable from an approval control sitting right next to the real one. (4) The semantics live only in gate-wiring.md, never at the point of use. Candidate remedies, none requiring a mechanism change: state the consequence inside the generated "## Pending sign off" section itself ("flipping this PR to ready approves the N items below; revert any you reject first"); relabel or drop the checkbox so it does not read as the control; and say plainly in gate-wiring that the marker is permanent history and approval is never recorded in the commit. Related: the ready-flip configurability issue planwright#379, which makes this worse if unaddressed, since an agent authorized to flip would be performing this approval on the operator's behalf.
