- 2026-09-14 [planwright] The 2026-09-14 worker-command-guard awk widening replaced a blanket |/> substring reject with a hand-written lexer, and a self-review lens pass found four working false-allows within an hour (arbitrary command execution and arbitrary file write, both guards). One root cause: the lexer division fallback is not inert - it re-enters comment and string scanning, so a regex misread as division can open a # comment or unbalanced quote that swallows a real pipe or redirect. Second: a / after the print/printf keyword reads as division because prev is the keyword last letter. Lesson: a shell-hosted partial lexer for a real grammar is the wrong shape for an allow-only security screen; narrow allowlisting of the specific safe forms (|| and bracket-free alternation) carries a fraction of the surface. Also notable: the agent that wrote the lexer wrote its 539-assertion suite, all green, and a dedicated adversarial sweep by a third agent found none of the four bypasses - shared-author blind spot is real and lens diversity is what caught it.
