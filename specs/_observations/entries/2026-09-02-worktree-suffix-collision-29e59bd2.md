CONFIRMED AS A CONTRACT VIOLATION, not a design tradeoff: fleet-dispatch-worktree.sh's own header states the suffix 'is a DETERMINISTIC function of (spec, task-id)' and then gives the form as 'task-<id>' -- the documented function takes the spec as an input the implementation never uses. AND IT FIRED, same day: dispatching model-allocation task 3 while fleet-lifecycle-closure task 3 was live switched the running worker's directory .claude/worktrees/task-3 onto the other spec's branch and reset it to main. Blast radius was limited only by luck -- the displaced worker had already committed and pushed its 5 commits and opened PR #387, and its tree happened to be clean; a worker mid-edit would have lost uncommitted work irrecoverably, with no warning at dispatch time. The helper does not check whether the target path is already occupied by a different branch, and there is no --suffix override to route around it. Two fixes, both needed: make the suffix actually spec-scoped as its own header promises, and refuse the dispatch when the target worktree exists on a different branch.
