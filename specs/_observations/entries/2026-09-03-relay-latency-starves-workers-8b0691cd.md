- 2026-09-03 [planwright] A missing gitignored file turns every dispatched worker into a request-response loop through human latency, and the throughput cost is an order of magnitude. MEASURED 2026-09-03 from worker event streams: workers whose commands escalated to the tower averaged 26 to 28 tool calls per hour (coc-5: 88 calls over 3.1 hours; ai-6b: 18 over 0.7 hours), while ai-7b, whose calls happened to fall inside the shipped worker-settings allow rules and so did not escalate, ran at 159 calls per hour. Six times the rate, same model, same machine, same session. coc-5 spent 3.1 hours to reach 88 tool calls and zero commits on a task that needs several hundred calls: a full day at that rate, under two hours unblocked. CAUSE: the auto-approve PreToolUse guard is wired through a per-project .claude/settings.local.json, which is gitignored machine-local config, so a freshly created worktree never has it. All seven active planwright worktrees lacked it. Every routine ls, cat, grep and test run therefore escalated to the operator, and the worker idled until answered. The visible symptoms this session (a 9-hour block on one unanswered request, repeated 2-hour stalls, five successive monitor rewrites chasing the stalls) were all downstream of this rate, and the rate itself was invisible until measured. WHY IT RECURS BY CONSTRUCTION: the config is machine-scoped (it references a machine path) but placed at project scope, so it must be recreated per worktree, forever, by hand. The gate script self-gates on PLANWRIGHT_WORKER_HANDLE and its own header states the blast radius is "enforced by env instead of file placement", so project placement buys no safety whatsoever. The fix is to wire the hook at USER scope in the dotfiles-managed settings.json, where it registers in every session including brand-new worktrees; a PR to inkatze/dotfiles is in flight. Note a fix that cannot work: the existing SessionStart worktree-bootstrap hook cannot write the file usefully, because settings are read at process startup, so a SessionStart write is too late for the session that just started and a dispatched worker only runs once. Operator-authorized interim mitigation applied the same day: the file was copied by hand into all seven worktrees plus the dotfiles checkout, and one clean-worktree worker was relaunched to pick the hook up; workers with uncommitted work were deliberately left alone.
