- 2026-08-26 [planwright] fleet-dispatch-worktree.sh names worktrees `task-<id>` keyed on the task id alone, so dispatching same-numbered tasks from different specs collides: a 3-unit dispatch (fleet-lifecycle-closure 1, concurrent-orchestrator-coordination 3, merge-currency-guard 3) silently checkout-switched the existing `task-1` worktree off model-allocation's open-PR branch and stole guard-coverage's parked `task-3` worktree twice in a row, leaving the middle unit's fresh branch with no worktree at all. Branches were unharmed (checkout moves only) and the tower repaired by hand (`git worktree add` under spec-qualified names, restoring `task-3` to guard-coverage), but the dispatch path should qualify the worktree name with the spec (e.g. `<spec>-task-<id>`) or refuse to reuse a worktree whose checked-out branch belongs to a different spec. The hazard is worst for parked units: guard-coverage task 3's park note points the operator at that worktree path for a manual seeding step, and a silent branch swap under them would have had the seed land on an unrelated branch.
