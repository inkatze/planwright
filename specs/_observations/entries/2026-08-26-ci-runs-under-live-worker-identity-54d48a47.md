- 2026-08-26 [planwright] Hazard class surfaced during fleet-lifecycle-closure Task 2 self-review, fixed in that guard but not addressed repo-wide. `mise run check` is routinely run INSIDE a dispatched worker, where PLANWRIGHT_WORKER_HANDLE and PLANWRIGHT_WORKER_SCOPE are set and PLANWRIGHT_FLEET_STATE_DIR is not -- so any check that executes a plugin script inherits a live worker identity pointed at the real fleet state root. check-hook-contracts.sh hit this directly: it executes registered hook handlers to verify their output contract, and fleet-liveness.sh hook stop / hook permission-request would have pushed real liveness transitions for whichever worker was running CI, corrupting the attention surface the operator reads. Fixed there by running handlers under `env -u PLANWRIGHT_WORKER_HANDLE -u PLANWRIGHT_WORKER_SCOPE PLANWRIGHT_FLEET_STATE_DIR=<scratch>`. Worth a sweep: any other check or test that invokes fleet-* scripts without redirecting the state root has the same exposure, and the existing test suites mostly do set PLANWRIGHT_FLEET_STATE_DIR but nothing enforces it. Candidate: a small guard asserting no script under scripts/check-*.sh reaches the default fleet root, or a shared test/CI helper that exports a scratch root once. Note a session hook already refuses direct writes to the live liveness/attention dirs, which is what caught this during review -- that guard is doing real work and its coverage could be widened to the same class.
