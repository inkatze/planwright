- 2026-09-25 [planwright] scripts/fleet-attention.sh queue --except ignores the exit status of its awk filter: sortable=$(printf ... | awk ...) keeps only the pipeline output, so an awk that dies before running (as one-true-awk did on a newline in -v before the ENVIRON fix) empties the queue and the stderr note reports every row as already handed to the operator. The failure mode is a pending human decision hidden from the queue render, the exact outcome the surrounding comment says --except must never cause. A guard that falls back to the unfiltered rows (or exits non-zero) when the filter fails would make any future awk-portability regression fail closed.
