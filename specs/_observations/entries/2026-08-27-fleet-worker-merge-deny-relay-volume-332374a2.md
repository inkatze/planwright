- 2026-08-27 [planwright] Fleet verification fan-out surfaced two operational gaps in the worker permission model. (1) The resolved worker profile hard-denies Bash(git merge:*) alongside the history-rewriting verbs, so a task branch that conflicts with main after a sibling PR merges cannot be resolved by the sanctioned 'relaunch the spec worker to resolve' path: the worker cannot start the merge, and converge-sync-main.sh aborts on conflict by design. The tower had to initiate 'git merge origin/main' in each conflicting worktree so the worker could resolve the conflicted file (add/commit/push are allowed). Plain git merge creates new commits and never rewrites history, so it does not violate the never-rebase/amend/squash/force invariant that motivates the other denies; consider either admitting plain merge to the worker profile, or giving converge-sync-main.sh a conflict-resolution mode the delegated worker can drive. (2) The worker auto-allow list covers only git status/diff/log/show/rev-parse/branch/checkout/switch/add/commit, scripts/*, and git push origin, so every routine read-only inspection (grep, shellcheck, shfmt -d, git ls-remote/merge-base/merge-tree, wc, mise run check/lint/test) and every /tmp-sandboxed probe prompts the tower. Under a multi-worker review fan-out this produces a very high volume of near-identical tower relay turns; widening the auto-allow list to read-only inspection shapes would cut most of that volume at the source.
