- 2026-09-07 [planwright] The model roster is now stated once (scripts/allocation-ladder.sh; PR 422 collapsed the four copies and made the ladder top escalation-only), but adopting a new model is still not purely additive. Two residuals were left deliberately out of that PR. FIRST, `tier_of_model` — the heavy/cheap split that `defer-heavy` withholds on — is spelled separately in scripts/fleet-allocate.sh, scripts/allocation-adapt.sh and scripts/fleet-usage-gate.sh, each as a literal case over alias names. An appended model matches none of them and `tier_of_model` returns 1, which is a fail-closed exit rather than a wrong answer, so the failure is visible; but three copies of one policy split is the same drift class the roster had. It IS derivable under append-only: heavy is rank >= rank(opus), which stays correct for anything appended above. SECOND, the per-tier withdrawal caps are one knob per model (fleet_cap_haiku/sonnet/opus/fable in config/defaults.yml) with a monotonicity check that names all four, so an appended model needs a new knob, a new default, and an edit to that check before it can be capped at all. Neither is urgent — nothing is adopting a model today — but both are what "a new model can be adopted by config" still costs, and whoever adds the next model will hit them in that order.
