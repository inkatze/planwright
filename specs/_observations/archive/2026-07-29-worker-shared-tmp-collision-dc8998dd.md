- 2026-07-29 [planwright] Concurrently dispatched workers collide on identical /tmp filenames, and the probability rises with fleet width rather than being random: workers follow the SAME skill instructions, so they independently choose the same obvious names. Observed 2026-07-29 with three workers active: two picked /tmp/panel-prompt.txt for their codex panel pass and one truncated the other mid-review (cat > truncates in place, same inode); the same session also had unqualified /tmp/ci2.log, /tmp/suite-results.txt and /tmp/q-test-fleet-*.log in play. A worker reading its own prompt file after a sibling rewrote it would review the sibling diff and report garbage findings against its own branch, which is silent and hard to attribute. Two candidate fixes: have the skills that write scratch files mandate a worker-scoped suffix (the dispatch already knows the worker id), or give each worker a private scratch dir via an env var set at dispatch (TMPDIR would do it for free, since mktemp and most tools honor it). The second is strictly better because it needs no per-callsite discipline and fixes tools that pick their own names. Related but distinct from worktree-suffix-cross-spec-collision, which is about worktree naming rather than scratch files.
