Reproduced verbatim against installed 0.31.0 AND the repo at HEAD (0.33.0) by piping the real payload shape; hook-remove is unaffected because WorktreeRemove really does carry worktree_path. Two compounding errors: (1) a configured WorktreeCreate hook REPLACES Claude Code native git worktree creation (docs: "Replaces default git behavior"; the CLI carries errors like "WorktreeCreate hook returned a path that is not a directory" and "the WorktreeCreate hook emitted a path with dot segments"), so the contract is that the hook CREATES the worktree from the given name and echoes where it put it, not that it passes a harness-supplied path through; planwright shipped a passive pass-through tracker against a decision-control creation contract. (2) obs a6f5511b recorded the contract as "echo the stdin worktree_path unchanged and always exit 0" and flagged the exact risk that a bad tracker "breaks all worktree creation fleet-wide" -- that risk has now materialized THROUGH the remedy that observation prescribed, so the observation itself needs superseding, not just the code.
